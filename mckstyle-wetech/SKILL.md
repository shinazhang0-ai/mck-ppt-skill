# MckStyle WeTech

生成具备顶级咨询公司水准的战略分析 PPT。输出为单文件 HTML 横向翻页格式，可直接在浏览器演示。

**在开始任何生成前，必须先读 `references/layouts.md` 和 `references/checklist.md`。**

---

## 核心原则（违反任何一条，专业感立刻崩塌）

### 内容原则

**1. 每页只有一个核心论点（One Message Per Slide）**
每张 slide 的标题必须是一个完整的、有观点的句子（Action Title），而不是话题标签。
- ✗ 错误：`市场分析`、`竞争格局`、`财务表现`
- ✓ 正确：`中国 SaaS 市场未来三年将以 35% CAGR 增长，头部效应加剧`
- ✓ 正确：`公司毛利率持续低于行业均值 8pp，根因在于渠道成本结构失衡`

**2. 金字塔结构（Pyramid Principle）**
- 整个 deck 的叙事遵循：结论先行 → 支撑论据 → 证明数据
- 每张 slide 的信息层级：Action Title（结论）→ Supporting Points（论据）→ Data/Evidence（数据）
- 绝不用 "首先…其次…最后…" 的流水账结构

**3. MECE（相互独立、完全穷尽）**
- 并列信息点之间不能重叠、不能遗漏
- 分类必须有明确的划分维度，不能混搭维度（如不能同时按地区和按产品线列举而不注明）

**4. So What 导向**
每个数据点后面必须有明确的含义："这个数字意味着什么？对决策有什么影响？"
- ✗ 错误：`转化率为 3.2%`
- ✓ 正确：`转化率 3.2%，低于行业均值 1.8pp，意味着每月损失潜在收入约 240 万元`

**5. 受众优先**
默认受众为 CEO / 董事会 / 投资人 / 战略决策层。他们时间有限，要求：
- 30 秒内能从标题行抓到全部关键结论
- 不解释"什么是 EBITDA"，但要解释"为什么这个 EBITDA 数字很重要"

### 视觉原则

**6. 克制且精准的视觉语言（综合 likaku 麦肯锡标准色系）**

色彩规则（严格执行，不妥协）：

| 角色 | 颜色 | Hex | 用途 |
|------|------|-----|------|
| 主色 NAVY | ██ | `#051C2C` | 封面背景、标题文字、圆形指标 |
| 强调色 | ██ | `#006BA6` | 关键数字、结论边框、高亮线条 |
| 正文 DARK_GRAY | ██ | `#333333` | 所有正文文本 |
| 次要 MED_GRAY | ██ | `#666666` | 标签、来源注释、轴标签 |
| 分隔线 | ██ | `#CCCCCC` | 表格行线、内容分隔 |
| 背景面板 | ██ | `#F2F2F2` | 内容块背景、Takeaway 区域 |

**四色并列系统**（仅在 3+ 个并列项时启用，用于视觉区分）：
- Blue `#006BA6` / Green `#007A53` / Orange `#D46A00` / Red `#C62828`
- 每个并列项取一色作为顶部边框（3px）或标签底色，配套浅色背景
- 绝不在单列页面上使用多色

绝不使用：渐变背景、阴影、3D效果、圆角卡片、emoji、装饰图标

**7. 数据可视化规则**
- 柱状图/折线图：必须有数值标签，必须有比较基准（行业均值、上期、目标值）
- 表格：用颜色区分正负（绿色/红色），但不用纯色块背景——用文字加粗或数值颜色
- 瀑布图（Waterfall）：拆解变化来源时首选
- 绝不用饼图（除非份额对比是唯一目的，且不超过 4 个分类）

**8. 留白即力量**
内容密度控制：每张 slide 最多 3 个支撑点，每个点最多 2 行文字。宁可拆成两页，不要堆满一页。

**9. 布局多样性（likaku v1.6 规则）**
连续 3 页或以上不得使用同一布局类型。一个 15 页 deck 的布局节奏参考：
封面 → 摘要 → 章节分隔 → 分析页 → 数据表 → 分析页 → 矩阵 → 章节分隔 → 分析页 → 时间线 → 分析页 → 建议页
布局单调是专业感崩塌的第二大原因（第一大是 Action Title 写成话题）。

**10. 字体四级制（对齐 likaku 22/18/14/9pt 标准）**
- **标题级**（Action Title）：`--fs-title`（≈20pt）粗体，颜色 NAVY
- **副标题级**（支撑点小标题）：`--fs-sub`（≈16pt）粗体
- **正文级**（bullet、说明）：`--fs-body`（≈14pt）常规
- **注释级**（来源、页码）：`--fs-footnote`（≈9pt）灰色

**11. 每页必备元素（likaku 必备规范）**
- Action Title（顶部，完整论点句）
- 页码（右下角，格式：`N / Total`，封面页不显示）
- 数据来源（底部，`来源：XXX | 日期`）
- 至少 2 个支撑证据（数据/图表/bullet）

## 工作流（6 步，严格按序）

### Step 0：需求澄清（必做，不跳过）

生成前必须确认以下 7 个问题（可一次性问完，用户回答后进入 Step 1）：

| # | 问题 | 目的 |
|---|------|------|
| 1 | 受众是谁？汇报场景？（内部战略会 / 董事会 / 投资人 / 客户提案） | 决定语气和深度 |
| 2 | 核心议题是什么？希望受众看完后做什么决定？ | 定义 deck 的终极 So What |
| 3 | 有没有原始素材？（数据、分析报告、旧 PPT、行业数据） | 有素材就基于素材，没有就帮他搭框架 |
| 4 | 时间限制？（10 分钟 ≈ 8 页，20 分钟 ≈ 15 页，30 分钟 ≈ 20 页） | 控制 deck 体量 |
| 5 | 有没有公司已有的品牌色？（如有，提供主色 hex 值） | 定制主题色 |
| 6 | 有没有必须包含或必须回避的内容？ | 避免返工 |
| **7** | **是否需要输出公司版（WeBank 品牌版）？** | **决定是否启用品牌 logo 和品牌色** |

**关于第 7 题——公司品牌版说明：**

如果用户选择「需要公司版」，生成时需做以下调整：

1. 在生成的 HTML 模板底部 `<script>` 里，将 `const BRAND_MODE = false` 改为 `const BRAND_MODE = true`
2. 这一行改动会自动触发：
   - WeBank logo 出现（内页 + 封面统一右上角，高度 20px/28px，透明度 0.7/0.9）
   - 强调色从 `#006BA6` 切换为 WeBank 品牌红 `#E31837`
   - 封面强调线（accent-bar）变为品牌红
   - 页面序号已隐藏（`.slide-number { display: none !important }`）
3. 其余设计规则（NAVY 主色、字体层级、内容逻辑）完全不变

如果用户选择「不需要公司版」，维持原始逻辑，`BRAND_MODE = false`。

**品牌版参考样例**：`assets/webank-brand-demo.html` 是一个完整的 WeBank 品牌版 demo deck，可直接在浏览器打开查看效果。生成品牌版时优先参考此文件的布局和配色。

### Step 1：搭建叙事骨架

基于澄清结果，在生成任何 HTML 之前，先输出大纲（Markdown 格式）：

```
## Deck 大纲

**核心结论（Executive Summary）**：[一句话总结整个 deck 的 so what]

| 页码 | Action Title | 类型 | 主要内容 |
|------|-------------|------|---------|
| 1 | [公司名] [议题] 战略分析 | 封面 | 副标题、日期、汇报人 |
| 2 | 执行摘要：[核心结论] | 摘要 | 3 个关键发现 + 建议行动 |
| 3 | [论点 1，完整句子] | 分析 | 支撑数据 |
| ... | | | |
| N | 建议行动与优先级 | 结论 | 行动项 + 责任人 + 时间线 |
```

**大纲确认后再生成 HTML，不跳过这步。**

### Step 2：生成 HTML Deck

读取 `references/layouts.md` 选择对应布局骨架，基于 `assets/template.html` 生成完整单文件 HTML。

关键技术约束（违反会导致视觉崩塌）：
- 所有图表必须用 SVG 内联实现，不依赖外部图表库（Chart.js 等可选 CDN 引入）
- 字体必须从 Google Fonts 加载：`Inter`（正文）+ `Inter Tight`（数字/标题）
- 颜色系统严格用 CSS 变量（见 `assets/template.html`）
- 每页 slide 必须是 `100vw × 100vh`，不允许内容溢出

### Step 3：自检

生成完成后，**必须**对照 `references/checklist.md` 逐项检查，P0 问题必须全部通过后才能交付。

### Step 4：用户反馈与迭代

接收用户反馈，90% 的调整只需改：
- Action Title 措辞
- 数据数值
- 颜色强调位置
- 内容密度（拆/合页面）

## 常见错误（真实踩坑记录）

### 内容类
- **标题写成话题而非论点**：`竞争分析` vs `竞争格局加剧，前 3 名占据 72% 市场份额`
- **数据孤岛**：给数字但不给 so what，受众自己去推理
- **结构不 MECE**：并列点之间有重叠，或遗漏重要维度
- **结论藏在最后**：咨询风是结论先行，不是推理到最后才揭晓

### 视觉类
- **颜色滥用**：超过 2 种主色 + 1 种强调色，视觉混乱
- **信息过载**：一页超过 3 个支撑点，或正文超过 25 个字/行
- **表格无重点**：数字一视同仁，没有用颜色/加粗标注关键数据
- **图表无基准**：只有绝对值没有对比，受众无法判断好坏

### 技术类
- **内容溢出 100vh**：slide 被撑破，演示时滚动条出现
- **SVG 图表坐标写死**：数值更新后图形位置不对
- **中文标题过长换行**：Action Title 超过 30 字必须换行处理（见布局文件）
